# Интеграция Яндекс.Календаря

**Статус:** Phase 0 — спецификация зафиксирована (2026-06-03)  
**Секреты:** `.env` + `CONTEXT.md` (оба в `.gitignore`)

---

## Цель

Подтягивать встречи из нескольких под-календарей Яндекса в планер **без мусора** (обеды, необязательные, встречи куда не ходим). Показ — **колонка 3 дашборда**, блок **над «Регулярными»**.

---

## Под-календари (из UI «Мои календари»)

| Календарь | Синк | Примечание |
|-----------|------|------------|
| встречи внутри груп… | ✅ | рабочий |
| встречи с заказчика… | ✅ | рабочий |
| календарь Далее | ✅ | |
| личные дела | ✅ | |
| **не обязательные** | ❌ | не подписываемся — уже отключён в UI |

CalDAV URL каждого календаря — из настроек Яндекса (поле CalDAV), подставляются в `YANDEX_CALENDAR_URLS` после discovery.

## Правила фильтрации

### Глобальные

1. **Выходные:** из **рабочих** календарей (первые три в таблице) события в **субботу и воскресенье** не импортируем.
2. Календарь `не обязательные` — не тянем вообще.
3. Отменённые (`STATUS:CANCELLED`) — skip.

### Пользователь: «Туда не пойду»

- Кнопка на карточке встречи в дашборде.
- Если событие **повторяющееся** (есть `RRULE` / master `UID`) → правило **игнорировать всю серию** (по `recurrence_id` или нормализованному заголовку).
- Если разовое → игнор только этот `external_uid`.
- Правила храним в `calendar_ignore_rules` (см. схему ниже).

**Пример:** «Лидирование команды Frontend» — еженедельно, статус «Возможно, пойду» → один клик «Не пойду» → больше не показывать в планере.

### Статус участия (Phase 2)

Опционально: не импортировать, если в CalDAV/описании статус «Возможно» / declined — если Яндекс отдаёт в `PARTSTAT` (проверить на реальных VEVENT).

## UI

- **Место:** `dashboard.html`, колонка 3, **перед** блоком `🔄 Регулярные`.
- **Заголовок:** `📅 Встречи` (или «Календарь»).
- Карточка: время, название, календарь-источник; кнопки: **«Не пойду»** (серия/раз), опционально «Скрыть сегодня».
- Сортировка по `start_at` на сегодня (+ опционально завтра в том же блоке).

## Данные

### `calendar_events`

| Поле | Тип | Описание |
|------|-----|----------|
| id | int PK | |
| external_uid | str UNIQUE | UID из iCal |
| recurrence_id | str nullable | master UID серии |
| calendar_key | str | slug/имя под-календаря |
| title | str | |
| start_at | datetime | |
| end_at | datetime | |
| location | str nullable | |
| is_recurring | bool | |
| planner_visible | bool | после фильтров |
| last_seen_at | datetime | |
| ignored_at | datetime nullable | |

### `calendar_ignore_rules`

| Поле | Описание |
|------|----------|
| rule_type | `series_title` \| `recurrence_id` \| `external_uid` |
| value | строка матча |
| created_from_event_uid | nullable | откуда нажали «Не пойду» |
| note | «Лидирование Frontend» |

## Сервис (не MCP как ядро)

```
app/services/calendar_sync_service.py   # CalDAV fetch, filter, upsert
app/services/calendar_filter_service.py # YAML + DB rules
config/calendar_sync.yaml             # дефолтные exclude-паттерны
```

**APScheduler:** каждые 30 мин + при старте приложения (окно: сегодня −1 … +14 дней).

**MCP (Phase 3):** тонкая обёртка `sync_now` / `preview` для Cursor — вызывает тот же сервис.

## Env

```env
YANDEX_CALDAV_USER=your_login@yandex.ru
YANDEX_CALDAV_APP_PASSWORD=          # см. CONTEXT.md, имя: planer_for_vera
YANDEX_CALENDAR_URLS=                # через запятую, после discovery
CALENDAR_SYNC_ENABLED=true
```

Пароль приложения создан в Яндекс ID → **Пароли приложений → Календарь**, имя `planer_for_vera`. Смена — только в ID, затем обновить `.env` и VPS.
